# 18_kdt_01 - 대구 북구 불법주정차 데이터 분석 프로젝트

대구광역시 북구의 불법주정차 단속·민원·CCTV·상습 발생지역 데이터를 통합 분석하여  
**시간·장소별 발생 패턴을 파악하고, 관리 우선지역을 도출한 뒤 지도 기반 웹 대시보드로 시각화한 프로젝트**입니다.

## 🎯 문제 정의

불법주정차는 차량 흐름 방해, 보행자 안전 위협, 긴급차량 통행 지장 등 도시 생활에 직접적인 영향을 줍니다.

하지만 단속 인력과 시간은 한정되어 있기 때문에 모든 지역을 동일한 강도로 관리하기는 어렵습니다.

따라서 다음 질문에 답하는 것을 프로젝트의 핵심 목표로 설정했습니다.

1. **언제** 불법주정차 단속이 집중되는가?
2. **어디에서** 반복적으로 발생하는가?
3. 단속·민원이 많은 지역에 **CCTV가 충분히 설치되어 있는가?**
4. 한정된 자원을 **어느 지역·시간대에 우선 투입해야 하는가?**

## 🧹 데이터 전처리

원본 데이터는 파일마다 기간, 컬럼명, 인코딩, 주소 표기 방식이 달라  
분석 전에 공통 형식으로 정리하는 작업이 필요했습니다.

주요 전처리 과정은 다음과 같습니다.

1. **파일 통합**
   - 연도별 CSV 파일 통합
   - `pd.concat()`을 이용해 하나의 데이터프레임으로 병합

2. **인코딩 처리**
   - `cp949`, `utf-8` 등 파일별 인코딩 차이 대응
   - 한글 깨짐 방지

3. **날짜·시간 변환**
   - 위반일자 → `datetime`
   - 연도, 월, 요일, 시간 파생변수 생성

4. **장소 정제**
   - 공백·특수문자·약칭 정리
   - 위반장소 문자열에서 동 이름 추출
   - 유사 장소명 표준화

5. **결측·중복·이상치 처리**
   - 핵심 컬럼 결측치 확인
   - 중복 행 제거
   - 북구 외 주소 및 비정상 시간값 확인

## 🧮 관리 우선도 점수 산정

관리 우선도는 총 100점으로 구성했습니다.

| 평가 항목 | 최대 배점 | 의미 |
|---|---:|---|
| 단속 발생량 | 40점 | 실제 불법주정차 발생 규모 |
| 민원 발생량 | 25점 | 주민 체감 불편 정도 |
| 시간 집중도 | 20점 | 특정 시간대 집중 정도 |
| CCTV 부족도 | 15점 | 감시 인프라 부족 정도 |
| **합계** | **100점** | |

각 지표는 서로 단위가 다르기 때문에  
**북구 전체 지역 내 상대 백분위**로 변환한 뒤 가중치를 적용했습니다.

```text
관리점수
= 단속점수
+ 민원점수
+ 시간집중점수
+ CCTV부족점수
```

> 관리 우선도는 공식 행정기관의 위험등급이 아니라  
> **본 프로젝트에서 정의한 상대적 관리 우선순위 지표**입니다.

## 🛠️ Troubleshooting

프로젝트 진행 중 다음 문제를 해결했습니다.

### CSV 인코딩 문제
- `cp949`, `utf-8` 등 파일별 인코딩 차이 해결
- 한글 깨짐 방지

### 상대경로 문제
- Jupyter Notebook이 `notebooks/` 폴더에 있어 데이터 파일 경로 오류 발생
- 프로젝트 구조에 맞춰 상대경로 수정

### 법정동 ↔ 행정동 차이
- 분석 데이터는 법정동 기준
- GeoJSON은 행정동 기준
- `map.js`에서 별도 매핑 처리

### 좌표 누락
대표 좌표를 다음 순서로 보완했습니다.

```text
불법주차 좌표
→ 민원 좌표
→ CCTV 좌표
→ 상습 발생지 좌표
```

### Flask JSON 변환 문제
- NumPy/Pandas 자료형
- `NaN`
- 날짜형

등을 일반 Python 자료형으로 변환하여 API 오류를 방지했습니다.

### Git 충돌
- 작업 전 `git pull`
- 담당 파일 분리
- 변경사항 공유

방식으로 충돌을 최소화했습니다.

따라서 본 결과는 정책 결정 자체가 아니라  
**집중관리 후보지역을 탐색하기 위한 참고지표**로 해석해야 합니다.


---

## 2. 매일 작업 순서

```bash
# 1. 작업 시작 전 최신 내용 받기
git pull

# 2. 코딩 작업

# 3. 변경 파일 추가
git add .

# 4. 커밋
git commit -m "작업 내용 설명"

# 5. GitHub 업로드
git push
```

> ⚠️ 작업 시작 전 `git pull`을 먼저 실행하면 충돌을 줄일 수 있습니다.

---

## 3. 자주 쓰는 Git 명령어

| 명령어 | 설명 |
|---|---|
| `git pull` | 원격 저장소 최신 내용 받기 |
| `git add .` | 변경 파일 전체 추가 |
| `git commit -m "설명"` | 변경 내용 저장 |
| `git push` | GitHub에 업로드 |
| `git status` | 현재 변경 상태 확인 |
| `git log` | 커밋 기록 확인 |

---

## 4. 충돌이 발생했을 때

- 같은 파일을 여러 명이 동시에 수정하면 충돌이 발생할 수 있습니다.
- 각자 담당 파일을 중심으로 작업합니다.
- 공통 파일 수정 전 팀원에게 공유합니다.
- 충돌 발생 시 변경 내용을 확인한 뒤 함께 해결합니다.
